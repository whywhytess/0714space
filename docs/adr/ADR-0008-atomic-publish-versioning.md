# ADR-0008：原子发布与不可变版本

- 状态：Proposed（待你签字）
- 日期：2026-09-17
- 相关：威胁 PUB-01/02、STORAGE-003；INV-2；ADR-0007

## 问题

发布需写入多文件到对象存储并更新 DB 指针。若非原子，中途失败会让线上出现半成品；重复/幂等请求可能产生错误版本；回滚需要能快速指回旧版本。

## 决定

- 文件写入绑定 `version_id`；`current_version_id` 只在**版本完整后单事务切换**。
- 发布任一阶段失败，线上仍提供旧版本；每次请求只看到完整单一版本。
- 重复请求用 `operation_id` / 幂等键去重，不产生错误版本。
- 对象 key 前缀用 immutable site UUID，用户输入不得直接拼桶根路径。
- 删除先 soft-delete，再异步删除对象，保留短期恢复窗口。

## 原因

原子切换 + 不可变版本是满足“数据正确性 > 发布原子性”的最直接方式，并与恢复一致性（ADR-0007）配合。

## 替代方案

- **就地覆盖文件**：发布中途即脏读、无法回滚；拒绝。
- **无幂等键**：重试风暴产生重复/错误版本；必须幂等。

## 后果

- 正面：发布可回滚、可重试、无半成品；恢复可按 version 定位。
- 代价：版本对象与 manifest 存储开销；需 GC 旧版本策略。
- 影响：M1 Gate（object versioning + 原子发布）；W7 专项。
