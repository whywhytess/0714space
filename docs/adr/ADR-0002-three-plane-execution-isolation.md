# ADR-0002：三执行面隔离（控制面 / 静态数据面 / SSI）

- 状态：Proposed（待你签字）
- 日期：2026-09-17
- 相关：威胁 XT-05/06、GW-01；INV-1、INV-6；v1.1 §4

## 问题

平台同时承担：控制面业务逻辑、海量不可信静态内容读取、以及对用户内容的动态 SSI 渲染。三者的信任级别、性能特征与故障模式完全不同；混在一个执行面会让任一面的故障或漏洞拖垮其他面。

## 决定

划分三个严格隔离的执行面：
1. **控制面**：Web(Next.js)、API(Fastify)、Admin。处理 Auth/Sites/Files 元数据/Follow/RSS/Billing。
2. **静态数据面**：Static Gateway(Go)。只做 Host/Path 路由、密码校验、Header policy、对象只读、ETag/Range、非阻塞统计事件。**不执行** SSI/Markdown/抓取/截图/解压/扫描/构建；写操作走 API/Deployment Service；使用只读对象存储凭证。
3. **SSI 执行面**：独立 SSI Renderer(Go/Rust)，gRPC/Unix socket 调用，可整体熔断。

用户代码不可访问控制面内网、数据库凭证、对象存储主密钥、队列、元数据服务。

## 原因

满足优先级“租户隔离 > 数据正确性 > 静态可用性”。静态读路径最简单、最可用；控制面持有敏感能力但不直接面向不可信内容；SSI 作为最危险的动态执行被单独隔离与熔断（见 ADR-0004）。

## 替代方案

- **单体应用同时渲染 + 托管 + 控制**：实现简单，但违反 INV-1/INV-6，任一漏洞即跨面；拒绝。
- **Gateway 内联 SSI**：省一次跳转，但 SSI 故障即静态 outage；拒绝（见 ADR-0004）。

## 后果

- 正面：故障域清晰；静态读路径可独立扩容与保障 SLO。
- 代价：跨面通信与部署复杂度上升；需网络策略与 IAM 边界。
- 影响：M1 Gate 要求“Static Gateway/SSI 边界”；Chaos 需验证各面独立故障。
